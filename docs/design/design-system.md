# デザインシステムの導入計画

次に UI を拡張するときは、[現行 UI の仕様](current-ui.md)から出発し、複数の箇所で意味を共有する色・余白・文字をトークンにする。トークンは、背景や補足文字などの用途を名前で参照できるようにした設計値。色の用途は Material Design 3 の考え方を参照し、キューブタイマーの状態には固有の名前を付ける。[Material Design 3 の色の役割](https://m3.material.io/styles/color/the-color-system/)

## トークンの置き場所と命名

現行の値は Tailwind のテーマと `TimerWorkspace` のクラスにある。下表は CSS へ移すときの候補。

| 層             | 用途                       | 候補                                                                                                                                         |
| -------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 基礎           | 実際の色、サイズ、間隔     | Tailwind の `--color-zinc-950`、`--color-indigo-200`、`--color-emerald-400` など                                                             |
| 意味           | 画面をまたいで共有する役割 | `--color-surface` → Zinc 950、`--color-surface-container` → Zinc 900、`--color-on-surface` → Zinc 200、`--color-on-surface-muted` → Zinc 300 |
| コンポーネント | 部品固有で調整する値       | `--timer-ready-fg` → Emerald 400、`--timer-running-fg` → Indigo 200。タイマーの状態に閉じた値として管理する                                  |

まず Tailwind の色を参照し、意味のある別名を Web 側の [globals.css](../../web/src/app/globals.css) に追加する。Tailwind のユーティリティとして使うものはテーマに載せ、特定の部品で使う変数はその部品の近くに置く。透過色は、実際に重なる背景と組み合わせて確認する。

名前は用途から決める。たとえばスクランブル操作のアクセントと計測中の数字は、同じ Indigo 200 を使っていても用途が異なる。将来、片方の色を調整できるようにする。

色の次は、セクション間の余白（現行20px）、パネルの角丸（現行24px）、補足ラベルの文字サイズ（現行12px）を共通化の候補にする。タイムの文字サイズは、画面幅に応じた切り替えや数字の桁揃えと一緒に、タイマー面の仕様で管理する。

## コンポーネントにする範囲

| 候補               | 再利用の範囲                                                  | 仕様に書くこと                                                               |
| ------------------ | ------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| セクションパネル   | 計測と統計から。新しい画面でも同じ階層を表すときに使う        | 背景、境界、角丸、内側の余白、見出し                                         |
| 操作ボタン         | 「次へ」など、同じ強調度と振る舞いの操作が増えたとき          | 通常、ホバー、押下、キーボードフォーカス、無効時の見た目とアクセシブルな名前 |
| 統計タイル         | Best と Ao 系から。別の練習集計でも同じ表示が必要になったとき | ラベル、値、補足、件数不足、長い値、幅による列数の変化                       |
| タイマー面・履歴行 | タイマー機能内で管理する                                      | 計測と履歴に固有の操作、状態、フォーカス、保存との関係                       |

色と間隔のルールを共有した後、役割と操作が揃う部品を抽出する。部品の仕様には次の項目を残す。

- 使う場面と実装箇所
- 使うトークンと、状態ごとの見た目
- ラベル、入力方法、狭い幅での挙動

## 実装に移す順序

1. **配色から始める。** 次に触る画面で、背景、パネル、文字、枠線を意味トークンに置き換える。変更前後の画面を同じ幅で見て、意図した差を確認する。
2. **再利用する部品を抽出する。** 利用箇所の状態と操作を揃えてから、共通部品を Web 側に置く。計測や保存の判断は機能側に置き、タイムの表示形式や統計計算は引き続き共有ドメインを参照する。
3. **実際の画面で使い方を確かめる。** 空、無効、計測中などの状態を実装と一緒にレビューする。画面が増えて組み合わせの確認が難しくなった段階で、部品を一覧できる方法を検討する。
4. **変更を文書に反映する。** 実装したトークン名と利用箇所を[現行 UI の仕様](current-ui.md)からたどれるようにする。将来ネイティブ版と共有する場合は、意味と値の共有を検討する。CSS と React コンポーネントは Web 側で管理する。

初回の移行では、補足文字の `zinc-500` と背景のコントラスト、タイマー面のフォーカス表示、狭い幅で1分を超えるタイムの表示を確認する。見た目や操作を調整する場合は、変更理由と確認結果を機能設計メモに残す。
